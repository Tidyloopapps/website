How to create recurring issues in Jira Cloud

Updated October 29, 2026

Weekly status reports, month-end close, quarterly access reviews: some work comes back on a fixed rhythm. Jira has no "repeat" button on a work item, so teams use one of three approaches.

1. Jira Automation with a scheduled trigger

  1. Go to Project settings → Automation → Create rule.
  2. Choose the Scheduled trigger and set how often it runs (a fixed interval or a cron expression).
  3. Add the action Create work item and fill in the summary, description and assignee. Add Create sub-tasks if you need them.
  4. Turn the rule on.

This is built in and flexible. Things to watch:

  • Tricky schedules need cron. "Last business day of the month" or "every second Tuesday" means writing and testing a cron expression.
  • Time zones. Check which time zone the rule runs in, especially around daylight saving changes.
  • Usage. From December 3, 2026, Atlassian bills Automation by steps, and every run of a scheduled rule counts against your plan's monthly allowance. Many recurring rules across many projects add up. Atlassian's page How is your automation usage calculated has the current numbers.
  • One rule per schedule. Twenty recurring tasks means twenty rules to maintain.

2. A recurring-work app

Marketplace apps let you set a schedule in plain language ("every weekday", "last business day of the month"), preview the next dates, and keep all schedules for a project on one page. Look for apps that run on Atlassian's own cloud, handle time zones per schedule, and don't use Automation rules, so they don't draw on your Automation allowance. We're building one: Recurring work by Tidyloop Apps (coming to the Atlassian Marketplace).

3. Clone by hand

Keep a template work item and use Clone each time. Fine for one or two items a month, easy to forget for anything more.

Tips that apply to every method

  • Put the date in the summary ("Status report – week 44") so recurring items are easy to tell apart.
  • Use a checklist in the description, or sub-tasks, for repeatable steps.
  • Pick one owner per schedule so nothing is created without someone to work on it.
